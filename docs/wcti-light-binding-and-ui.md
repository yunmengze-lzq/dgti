# WCTI 轻量绑定、羁绊与 UI 原型说明

> 版本：v0.1  
> 对应原型：`src/views/WctiExperience.jsx` + `src/wcti.css`

## 1. 当前原型做了什么

- 用本地浏览器生成一个短 `userId`，不要求注册。
- 用户可填写一个「厕格代号」和一个可选共同语境。
- 答题草稿、结果、羁绊账本都保存在 `localStorage`。
- 测完后生成个人羁绊码，例如 `WCTI-LIVE-DZ9D2K`。
- 用户可主动输入别人的羁绊码、关系类型和对方代号，生成一条本机羁绊记录。
- 羁绊记录只表达「用户主动声明的关系」，不自动读取通讯录、微信、公司、手机号或真实姓名。

## 2. 羁绊数据建议

正式后端可以把羁绊做成独立表，不要和研究答卷、地址、支付或物流表直接混放。

建议字段：

| 字段 | 说明 |
|---|---|
| `edge_id` | 羁绊记录 ID |
| `from_user_id` | 发起方轻身份 ID |
| `to_user_code_hash` | 对方羁绊码哈希或对方轻身份 ID |
| `from_type_key` | 发起方人格类型 |
| `to_type_key` | 对方人格类型 |
| `relation_label` | 用户主动选择的关系，如同事、同组、朋友 |
| `context_label` | 用户主动填写的共同语境，可选 |
| `bond_name` | 生成的羁绊类型，如同格互照、隔板互补 |
| `bond_score_band` | 建议存区间，不公开精确计算权重 |
| `confirmed_state` | 单向记录 / 双向确认 / 已撤回 |
| `created_at` | 创建时间 |
| `survey_version` | 产生结果的问卷版本 |

不建议收：

- 手机号、真实姓名、公司全称、通讯录、微信 OpenID。
- 精确地理位置。
- 可以反推现实小团体的公开榜单。
- 未经对方确认的「谁和谁关系最好/最差」排名。

## 3. 产品体验原则

羁绊是结果页后的轻社交延展，不应该成为答题前的利益诱导。

可以做：

- 测完后生成个人羁绊码。
- 双人结果卡：`活人感开门人 x 望周知撤退者 = 门口会谈`
- 小队类型图：只展示 3 人以上、主动加入的小队聚合。
- 关系类型由用户主动选择。
- 对方可二次确认或撤回。

不要做：

- 自动匹配附近的人。
- 公开展示某公司、某部门、某宿舍的稀有类型。
- 把羁绊数量做成强排名。
- 把实体徽章资格和某种人格或某种羁绊强绑定。

## 4. UI 参考方向

参考 16Personalities：

- 16 类型矩阵。
- 四个角色组使用稳定色彩。
- 结果页先给类型名、匹配度、被理解感文案。
- 延展到关系、团队、互相理解，但不声称能判断现实个人。

参考 SBTI：

- 无需注册，即测即看。
- 题量在 30 题左右，首版原型先用 8 题跑通节奏。
- 结果代码短、好截图。
- 文案可以荒诞、嘴损、自嘲，但不给用户做道德判决。

WCTI 自己的差异：

- 视觉中心是接近 MBTI 语法的 2D 平面人格插画，但角色名、梗点、姿态、道具和商品锚点全部重新原创。
- 答题进度不是普通 stepper，而是「角色匹配进度」。
- 结果产品不是广告位，而是人格结果的实体化。
